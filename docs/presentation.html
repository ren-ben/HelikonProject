CLIL

Content and Language Integrated Learning — students learn a subject and a foreign language at the same time. Coyle's 4Cs framework defines the four pillars:

Content — the subject knowledge being taught
Communication — the target language skills
Cognition — higher-order thinking skills
Culture — intercultural awareness

The RAG Pipeline

Five stages transform a raw document into AI-generated, source-cited educational material

STEP 01
📄

Ingest

Teacher uploads PDF or DOCX. The system extracts text page-by-page and splits it into overlapping chunks.

PDF → PyPDF2
1000 chars / chunk
200 char overlap
STEP 02
🧮

Embed

Each text chunk is converted into a high-dimensional vector (1536-d) using OpenAI's embedding model.

text-embedding-3-small
"Biology cell..."
→ [0.023, -0.41, ...]
STEP 03
💾

Store

Vectors are stored in ChromaDB alongside metadata: page number, filename, subject, and user ID.

ChromaDB (cosine)
metadata: page, file,
subject, user_id
STEP 04
🔍

Retrieve

A query is embedded the same way, then cosine similarity finds the top-k most relevant chunks from the database.

score ≥ 0.7 relevance
STEP 05
🧠

Generate

Retrieved chunks are injected as context into the LLM prompt. The model generates a response with inline citations [1][2].

Theory — Under the Hood

RAG in Code

The actual Python pipeline running in our service

rag-service / generation.py
# 1. Teacher uploads a document — we chunk and embed it
from langchain.text_splitter import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(
chunk_size=1000, chunk_overlap=200
)
chunks = splitter.split_text(document_text)
# 2. Store in ChromaDB with metadata
collection.add(
documents=chunks,
metadatas=[{"file": name, "page": pg, "subject": subj}]
)
# 3. Query: find relevant chunks via cosine similarity
results = vectorstore.similarity_search_with_score(
query="Explain cell division in English",
k=8,
filter={"subject": "Biology"}
)
# 4. Inject as context → LLM generates with citations
context = "\n".join(f"[{i}] {doc}" for i, doc in results)
response = llm.invoke(prompt + context) # → "Cells divide via mitosis [1]..."

Prompt Engineering

System Prompt Engineering

How we keep LLM outputs stable, structured, and on-task

Structure

Markdown Hierarchy

Headers (H1–H3) create a structural skeleton the model follows. Sections delimited with clear separators prevent bleed-through.

Stability

Instruction Reinforcement

Critical constraints are repeated at multiple points. Redundancy prevents instruction drift in long generations.

Safety

Guardrails

Explicit boundaries prevent the model from deviating — format, length, language level, and topic constraints enforced in every prompt.

Quality

Validation Rubrics

Requirements map directly to rubric criteria, enabling automated evaluation of whether outputs meet specifications.

Prompt Engineering

User Prompting Strategies

Techniques that maximize output quality at inference time

Few-Shot Prompting

2–3 examples in-context dramatically reduce output variance and anchor the model to expected formats.

Chain-of-Thought (CoT)

Step-by-step reasoning traces improve accuracy on complex tasks. "Think through this step by step."

Persona Prompting

Persona prompting is a technique where you assign a specific role or professional identity to the AI to tailor its expertise, tone, and perspective to a particular task.

Hallucination Mitigation

Anchoring responses to retrieved document context prevents fabrication. "Only use the provided sources."

Validation Frameworks

LLM-as-a-Judge Pattern

Traditional metrics (BLEU, ROUGE) fail for semantic quality — LLMs evaluate LLMs

📊

G-Eval

Chain-of-Thought evaluation for subjective criteria: coherence, helpfulness, pedagogical value.

Best for: Qualitative rubrics
✅

QAG

Binary claim verification — extracts claims from output and checks each against source documents.

Best for: Faithfulness checking
🌳

DAG

Decision trees for structured evaluation workflows — branching logic for complex rubrics.

Best for: Multi-step validation
Validation Frameworks

The 5 Metric SLO Strategy

Balanced metric portfolio — custom + generic + reference-less

1–2 Custom

G-Eval or DAG for domain-specific criteria tailored to CLIL pedagogical requirements

2–3 Generic

QAG for Faithfulness, Answer Relevancy — universal metrics that apply across all output types

SelfCheckGPT

Reference-less hallucination detection via sampling — no ground truth needed

Each metric feeds a Service Level Objective — automated alerts when quality drops below threshold

Validation Frameworks

Human Oversight Patterns

Automation handles volume — humans handle judgment

HITL

Human-in-the-Loop

Active approval before output is delivered. Required for high-stakes content like assessments and exams.

HOTL

Human-on-the-Loop

Supervisory monitoring with override capability. System runs autonomously, humans audit asynchronously.

SME

SME Calibration

Subject matter experts design evaluation rubrics and curate gold standard datasets for validation.

Flywheel

Improvement Cycle

Errors feed back into gold datasets, which drive fine-tuning — a continuous quality improvement loop.

Production Challenges

Production Challenges

The gap between benchmarks and real-world deployment

1

Evaluation Gap

Benchmarks test clean data — production faces ambiguous queries, typos, and multi-language input. Test on real usage.

2

Structured Output Validation

Use STED (Semantic Tree Edit Distance) with Hungarian Algorithm for JSON schema validation of complex outputs.

3

Performance Drift

Model quality degrades silently over time. Continuous monitoring with SLO thresholds catches regressions early.

Summary

Key Takeaways

Local LLMs deliver operational sovereignty — full control over data, latency, and model behavior.

System prompts are the constitutional layer; user prompts are the execution layer.

Automated judges (G-Eval, QAG, DAG) replace word-overlap metrics for semantic evaluation.

Human oversight feeds a continuous improvement flywheel — errors become training data.

Multi-layer security is essential for production RAG — input validation, guardrails, output verification.
